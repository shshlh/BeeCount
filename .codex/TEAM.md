# 团队协作章程 · Fork & Invest

本文档是本项目的**指挥中心**。任何新会话（团队角色）启动后，第一件事就是读取本文档，了解项目状态、自己的任务和当前进展。

---

## 工作流程

```
PM 创建/指派任务 → 角色线程独立工作 → 任务完成更新本文件
→ PM 审查 → 合入基线 → 进入下一轮
```

**核心规则**：
1. 每个线程（会话）是一个独立团队成员
2. 所有共享状态写在本文件中
3. 任务完成后必须更新本文件的「任务板」状态
4. git 提交作为唯一的代码交付物
5. PM 负责审查合入

**同步机制**：
- 每个任务开始时，阅读本文档 → 确认当前状态
- 每个任务结束时，更新本文档的任务板
- 当会话恢复或上下文切换时，重新读取本文档

## 任务分派工作流

### PM 分派任务

1. PM 在本文件任务板中将任务标记为 🔄 进行中，填写负责人
2. PM 创建新线程，传入：
   - 要读的文档路径（本文件 + PROJECT_PLAN.md）
   - 具体任务描述
   - 相关的文件引用
   - 已知约束/架构决策

### 角色执行任务

1. 读取 docs/TEAM.md → 确认自己的任务
2. 读取 docs/PROJECT_PLAN.md → 理解背景
3. 读取任务相关的现有代码 → 理解上下文
4. 实现任务
5. 更新本文件任务板（标记 ✅）

### PM 审查合入

1. 审查代码（按 bug/风险/测试缺失/风格问题排序）
2. 要求修复问题
3. 确认修复后合入主分支
4. 更新任务板 → 进入下一任务

## 图像识别规范（读图/截图/参考图）

当任务涉及图片（用户发图、截图、本地图片文件、URL、图表/UI 参考图）且当前模型不支持图像输入时，**必须使用 deepseek-vision-skill** 获取图片描述，再基于描述继续工作。

**触发场景**：
- 用户引用本地图片（如 D:/Users/wanji/Downloads/首页.jpg）
- 需要 OCR / 截图内容 / UI 视觉检查
- 消息中出现「image content omitted because you do not support image input」

**用法**（脚本在 C:/Users/wanji/.codex/skills/deepseek-vision-skill/scripts/describe-image.js）：
- 本地图片：node "C:/Users/wanji/.codex/skills/deepseek-vision-skill/scripts/describe-image.js" "图片路径"
- 用户刚发的图：node "...describe-image.js" --latest
- 带问题：node "...describe-image.js" --prompt "具体问题" "图片路径"

**要求**：
- 用脚本输出的事实描述，OCR 文本必须原样引用，不得臆测
- 脚本依赖网络与 API key（config.json）；失败时告知用户并提供替代方案
- 图片描述仅用于理解需求，不写入最终交付物（除非用户要求）

## 跨会话交接协议

当一个线程完成任务后交接给另一个线程：

1. **git 提交**：所有变更必须提交，commit message 写明做了什么
2. **更新任务板**：本文件的任务板标记 ✅
3. **写交接记录**：在 docs/HANDOFF.md 模板正下方插入新记录（最新在前，按日期倒序）

### HANDOFF.md 编辑铁律（防止历史丢失）

- **只增不减**：任何编辑只允许「新增」内容，绝不允许删除/覆盖已有记录
- **禁止整文件重写**：不得基于过期快照用 Python/PowerShell 重写整个文件；新增记录用唯一锚点（新记录的「**任务**：5.x」标题）定位插入，或只在模板正下方 prepend 一个固定块
- **禁止模糊正则范围替换**：不得用匹配 ## 2026-08-02 / --- 这类重复标题的正则做范围删除或替换
- **编辑后自检**：每次改完 HANDOFF 立即运行
  git diff -- docs/HANDOFF.md
  除了 --- a/docs/HANDOFF.md 这一行外，不允许出现任何以 - 开头的内容行；出现即说明删除了历史，必须恢复
