# 团队协作章程 · Fork & Invest

本文档是本项目的**指挥中心**。任何新会话（团队角色）启动后，第一件事就是读取本文档，了解项目状态、自己的任务和当前进展。

---

## 工作流程

```
PM 创建/指派任务 → 角色线程独立工作 → 任务完成更新本文件
→ PM 审查 → 合入基线 → 进入下一轮
```

**核心规则**：
1. 每个线程（会话）是一个独立团队成员
2. 所有共享状态写在本文件中
3. 任务完成后必须更新本文件的「任务板」状态
4. git 提交作为唯一的代码交付物
5. PM 负责审查合入

**同步机制**：
- 每个任务开始时，阅读本文档 → 确认当前状态
- 每个任务结束时，更新本文档的任务板
- 当会话恢复或上下文切换时，重新读取本文档

## 任务分派工作流

### PM 分派任务

1. PM 在本文件任务板中将任务标记为 🔄 进行中，填写负责人
2. PM 创建新线程，传入：
   - 要读的文档路径（本文件 + PROJECT_PLAN.md）
   - 具体任务描述
   - 相关的文件引用
   - 已知约束/架构决策

### 角色执行任务

1. 读取 docs/TEAM.md → 确认自己的任务
2. 读取 docs/PROJECT_PLAN.md → 理解背景
3. 读取任务相关的现有代码 → 理解上下文
4. 实现任务
5. 更新本文件任务板（标记 ✅）

### PM 审查合入

1. 审查代码（按 bug/风险/测试缺失/风格问题排序）
2. 要求修复问题
3. 确认修复后合入主分支
4. 更新任务板 → 进入下一任务

## 跨会话交接协议

当一个线程完成任务后交接给另一个线程：

1. **git 提交**：所有变更必须提交，commit message 写明做了什么
2. **更新任务板**：本文件的任务板标记 ✅
3. **写交接记录**：在 docs/HANDOFF.md 底部追加一条记录

### 交接记录模板

```
## {日期}

**移交角色**：[角色名]
**接收角色**：[角色名]
**完成工作**：
- 改了哪些文件
- 做了什么变更
- 还有什么未完成

**下一个任务需要知道的**：
- 关键决策
- 已知问题
- 要读的代码上下文

**git 状态**：当前分支 [branch name]，已提交 [commit hash]
```
